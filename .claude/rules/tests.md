# Tests in dstack

- **Whole-device tests** (`tests/system_clock.rs`): the host refuses loopback (no MAC, unreachable for Dante), so run the device on the box's routed IPv4 (`UdpSocket::connect` to 192.0.2.1:9, then `local_addr`; sends nothing). Each test binds the Dante ports on that address: take the file's `ONE_DEVICE` lock.
- **Shared dev box:** dcontroller (another account on dev1) runs `dstack-dev` in its own E2E on the same routed address and Dante ports. A whole-device test that fails at once on its start (bind) while one of theirs runs is that collision. Rerun it alone and check `ps -eo user,args | grep dstack-dev` before calling it ours (1.11.2026: `tests/embed.rs` failed once in 0.01 s, passed 7 times after).
- **Timing on CI and dev boxes:** a normal-priority TX thread wakes over 1 ms late now and then; at the test config's 1 ms latency that restarts the TX schedule (a 2 to 5 ms RX dropout). Whole-path tests use a 10 ms latency, take their counts after the start (0.1 s of RX read), and require no restart and every packet within the latency; real-time lateness is the hardware gate's, never a shared runner's.
- **Check the Windows build before a push:** `cargo clippy --target x86_64-pc-windows-gnu --workspace --all-targets --locked -- -D warnings` (the target is on dev1 since 2.11.2026). An unused import under `cfg(unix)` costs a 20-minute CI round otherwise (0.4.34 took three).
- **Windows CI runs every test:** paths must be absolute on Windows too (`std::env::temp_dir()`), not `/run/...`.
- **Async inputs:** the directory's ARC and DBC records come from separate browse threads; wait for every record a lookup needs before it (a lookup without them registers no want).
- **Mutation gate:** per mutant only the unit tests and `tests/hot_path.rs` run (`.cargo/mutants.toml`); a whole-device test cannot run per mutant (ports). A test bound inside a step must carry the step's own time (`Instant` around `step`), not a fixed bound. Host glue that only calls `daemon::serve` (`host::serve_device`) is covered by the whole-device test alone: any edit inside it, a comment too, puts its `Ok(())` mutant in the diff and fails the gate. Leave such functions out of cosmetic changes.
- **Fake time vs real time:** TX lateness adds real time inside a step to the fake PTP time; bound it by the measured step duration.
- **Captured logs:** a test that captures logs with `tracing::subscriber::with_default` calls `crate::test_log::undecided()` first. Without it, tracing's callsite interest cache can keep "never" for a callsite another test thread hit first, and the capture comes back empty about 1 run in 4.
- **Equivalent mutants:** combine disjoint bit fields with `from_be_bytes`, not `(a << 16) | b`. cargo-mutants turns `|` into `^`, which gives the same value, so the mutant cannot be killed. Likewise `2 * X` with a constant X = 2 equals `2 + X`: write sums (`X + S + X`), not the product (dtray's icon, v0.6.15).
- **Inside a `.claude/worktrees/` worktree** `cargo fmt --all` fails: `vendor/mdns-sd` resolves the main checkout's workspace. Check with `rustfmt --check --edition 2024` on each crate root (`crates/*/src/lib.rs`, `main.rs`, Windows-only module files) instead; it follows the `mod` tree.
- **A local test device for a reader (dtray):** `dstack-dev --config <cfg> --ip <routed IPv4> --clock system --control <short path>`, stopped with `kill -INT`. The control socket path must fit SUN_LEN (about 107 bytes): a scratchpad path is too long, so use a short `/tmp/<dir>/c.sock`.
- **dtray's expected devices in a check:** `DSTACK_DEVICES_DIR=/tmp/<dir>/devices dtray --print` reads that folder instead of `/etc/dstack/devices`; an empty `<name>.device` there with no running device prints "<name>: expected, not running".
- **A warn-once flag** (`!flag.swap(true)`): the test makes at least three refusals and counts one warning. With two, the `delete !` mutant (warn from the second on) also warns once and survives (v0.6.18, `Media::app_status`). A warning that depends on an error kind goes in a pure function returning the text (`expected::unreadable`): two arms that both return empty leave the guard's mutants unkillable otherwise.
- **Warnings from a background thread:** `capture_warnings` sees only its own thread's events. A warn-once raised on a worker thread (the app hook's `dstack-app-status`) cannot be counted, and its guard's mutants survive. Let the thread mark the state and warn on the reader's thread (`AppHook::read`, v0.6.19).
- **dtray's Linux tray on dev1:** building it needs `libgtk-3-dev` and `libayatana-appindicator3-dev` (installed on dev1; CI's apt step). With no display, `env -u DISPLAY -u WAYLAND_DISPLAY dtray` must exit 1 at once ("no desktop ... (GTK)"). To check that it runs, use `xvfb-run -a dbus-run-session -- ...` with a temporary `XDG_RUNTIME_DIR` (mode 700). The first instance keeps running and a second start exits 0. `--autostart on` with a temporary `XDG_CONFIG_HOME` writes an entry; check it with `desktop-file-validate`. Wayland's clipboard is not checked this way.
- **Windows GUI checks from dev1:** the Windows boxes on MCP cannot fetch a file from dev1. There is no route to dev1's addresses, the public drop is behind Cloudflare Access, and no box has Rust. Pushing a 6 MB binary through `FileUpload` would mean base64 in the context, which is not workable. A Windows desktop check needs a CI artifact or another transfer path first.
- **Live tests on dev1's Dante NIC** (`dante-net`; the address is in the private config): run the device with `--ip <that address>` and a private config, write its pid to a file, and stop it with `kill -INT <pid>`, which sends the goodbyes. Never use `pkill -f <pattern>`: it also matches the shell running the command and kills it. The ctl `status` request counts show which ARC and 8700 opcodes Dante Controller sends; the once-a-minute "not answered" warning lists the gaps.
- **Unreachable guards:** a run-time check that can never be false, given what the code before it already limits, is a mutant no test can kill. Prove the bound once with `const _: () = assert!(...)` and drop the check (example: the fpp step in `subscribe.rs`: 9 + 8 * 4 * 32 <= 1472).
- **Windows-only code and the gate:** the mutation gate runs on Linux, so mutants in `cfg(windows)` code can never be caught. `clock/sys_windows.rs` is excluded in `.cargo/mutants.toml`. Keep Windows logic that matters in cross-platform functions with tests (e.g. `clock::wait_mode_for`, `clock::realtime_for`), and leave the `cfg(windows)` part as thin glue.
- **Latency verdict = a real receiver's records, never our counters** (owner, 31.10.2026). Dante heartbeats (224.0.0.233:8708) carry per RX flow slot: record 0x8003 = that second's peak lateness in samples, 0x8004 = cumulative late count (header: count, 0, offset of the values). Map slot to transmitter with ARC 0x3000 + 0x3200 (page body `0,1,start,0,0`). Probe: `~/.claude/work-products/dstack/rxlat.py <our ip> <receiver ip> <s>` (exit 1 on late or peak over latency). Every gen3 fault tonight (deep C-states, TX/RX same FIFO priority on one core, fq_codel qdisc) was invisible to our counters; checklist in `docs/linux-box.md`; Windows (FOH PC, 1.11: spinning threads on the NIC's RSS CPUs, a NIC shared with bulk TCP) in `docs/windows-box.md`.
- **The IEM card is shared with iemmixer's box:** use only card RX 104/105, tell iemmixer before subscribing, unsubscribe and stop the dev1 device after; a second sender on the card spoils its measurements.
- **Constant bounds:** clippy refuses `assert!` on constants inside a test; put `const _: () = assert!(...)` next to the constant.
- **Windows runners refuse some high ports** (excluded port ranges, WSAEACCES 10013): a test never binds a fixed port near 65535 and never relies on binding in order to reach a range check (v0.4.39: the RX port-base test failed on 65531). Pure range logic gets a pure function and a boundary test.
- **Probing hardware on 8700:** a device answers on the info group 224.0.0.231:8702, from its own port, with its own sequence number (not the request's). Match a reply by source address and reply opcode, never by seq. Dante Controller caches a device's answers: to capture its full read sequence, restart DC under the capture (pktmon on mbc, filtered by control ports, without the 614xx audio range).
- **Socket loops and the gate:** put each read's decision (hand on, go on after a timeout, end on an error) in a pure function that takes the `io::Result`, and unit test every arm (`latency::hand_on`). On dev1 other devices' heartbeats fill every gap, so a test cannot count on a read timing out on a real group socket.
- **A consumer reports silence:** first read its device from dev1's Dante NIC, read-only. Find its ARC port with `avahi-browse -t -r -p _netaudio-arc._udp`. The 0x3000 page gives each RX channel's TX channel and device, and its status word at bytes 12-15 of the entry (`subscribe/sub_status.rs`). The heartbeat's 0x8003 record gives the device's rate. 3.11.2026: the intercom read 21 on all four channels, from a 48 kHz device on a 96 kHz network.
- **Filters in whole-device tests:** a FIR rings on a step from silence (about 7 % over for the 2:1 half-band). Assert the settled level (the last sample), never the peak.
- **A receiver's flow request fails (status 21 at the receiver):** capture its request at the receiver with pktmon (mbc: `pktmon filter add -i <tx ip> -t UDP -p <flows port>`, then `etl2txt -v 3 -x`). Parse the payload with `dstack::flows::control::parse_request` in a throwaway example. Our answer's status is in the reply (0x0302 and so on). 3.11.2026: DVS asked fpp 60 whatever we advertised. Prove a cause before shipping a fix for it: the missing `_netaudio-dbc` looked like a cause the same night, and was not.
- **A gate chain that greps its own output never stops:** `cargo clippy … | grep …; git commit` commits even when clippy failed (the pipe's status is grep's). Read the output before the commit, or commit in a separate call. 3.11.2026: a commit missed a Windows caller this way, and the next commit fixed it.
- **The local mutation gate** is cargo-mutants 27.1.0 (as CI) since 3.11.2026. Run it as CI does: `NEXTEST_PROFILE=mutants cargo mutants --in-diff <diff> --baseline=skip --timeout 60 -j 4 --test-workspace=true`. Without `--baseline=skip` the baseline runs `cargo test -p <crate> --test hot_path` and fails for a diff in dlink or dstack-resample alone (3.11.2026).
- **Thread stress tests on runners:** a spawned thread can start tens of ms late on a runner, which never happens on dev1. Before calling a stress-test fix done, reproduce the runner's order locally with a temporary `sleep(50 ms)` at the thread's start (v0.6.8: the ring's reader started late; with no read yet `write_at` has no early check, and the test failed twice on CI after passing 15/15 locally). Prime the shared state the check needs (`read_at` before the writer) instead of loosening the invariant.
- **Exclusion patterns match prefixes:** `.cargo/mutants.toml`'s `exclude_re` entries are regexes over the mutant's name (`tx.rs.*send_one`), so a new function named `send_one_retrying` would be excluded silently and its mutants never tested. Name a new tested helper so no exclusion matches it (v0.6.21: `send_with_retries`).
- **A wait loop with a comparison** (`while start.elapsed() < d`) leaves the `<` to `<=` mutant, which waits the same and cannot be killed. Write it without a comparison: `while !d.saturating_sub(start.elapsed()).is_zero()`, and test that it waits at least `d` (v0.6.21, `media::tx::spin_for`).
- **Retry loops in the TX pass:** keep the loop generic over closures (`send`, `age`, `wait`; `media::tx::send_with_retries`) so a unit test drives it with a fake send that fails with given OS codes; the real socket never refuses on demand. Generic closures keep the hot path allocation-free.
- **dlink's pump block is 128 frames by default** (v0.6.20, #90), not the stack's `stream::BLOCK` 32. Its whole-device expectations follow it: `pump.offset` = B + P + W (608 at 48 kHz, 816 for a 48 kHz app on a 96 kHz device), and a 48 kHz app on a 96 kHz device gets 64 frames a block. A dlink test about something else that needs 32-frame blocks sets `.block(32)`. W is `dlink::work_margin`: the block, at least 2 ms. P is not set but split from the 10 ms budget (`dlink::split`, v0.6.22, #68): a test pins a P only from `split`'s numbers, and the loop test (`tests/link.rs`) checks them against a step sent through our own flow.
