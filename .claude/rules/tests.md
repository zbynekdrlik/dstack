# Tests in dstack

- **Whole-device tests run on loopback** (#366, `host::test_run`): every process cargo runs in this workspace has `DSTACK_TEST_LOOPBACK=1` (`.cargo/config.toml` `[env]`, nextest and cargo-mutants included), and then the host serves a device on 127.0.0.1 (a test MAC `02:00:7f:00:00:01`) and REFUSES any other address the lookup finds unless `DSTACK_LIVE_TEST=1` (a place not there yet is judged as in production, so the "address not there" start tests still run). Each file's `test_ipv4()` returns `Ipv4Addr::LOCALHOST`; never probe the routed address (192.0.2.1:9) for a device again: on dev1 that announced ~35 mDNS datagrams/s per binary on the LAN leg, the top senders on FOH's Dante leg (dasio#127). Loopback multicast works on Linux and Windows (`IP_MULTICAST_IF` 127.0.0.1, a member joined on 127.0.0.1). A test binary run directly (`target/debug/deps/system_clock-*`) has no variable: production refuses loopback, so run it through `cargo test` or with `DSTACK_TEST_LOOPBACK=1` set. Each test binds the Dante ports on 127.0.0.1: take the file's `ONE_DEVICE` lock. A test that sends multicast with its own socket (`mdns_answer_only`, the mDNS meter's) uses 127.0.0.1 too; the guard covers only devices the host starts. Count dev1's own mDNS on both legs with a `python3 -I` listener on 224.0.0.251:5353 joined on each leg's address (counts by source; the kernel loops our own sends back): while the whole set ran (150 s, 17.11.2026) 0 on the Dante leg and 2 on the LAN leg, from no device of ours (before: `system_clock` alone sent 780 there in 22 s). The guard judges the address the lookup FOUND (`TestRun::admit`), never the place asked: a first draft refused every non-loopback place up front and broke the dlink start tests on an absent address. On loopback the load-sensitive dlink tests stay load-sensitive (`a_pump_late_within_its_margin_keeps_the_tone_whole` failed 1 of 2 at load 20, passed 5 of 5 under `DSTACK_TEST_LOOPBACK=1 chrt -f 10 <binary>`).
- **Shared dev box:** dcontroller (another account on dev1) runs `dstack-dev` in its own E2E on the routed address and Dante ports; since #366 ours are on 127.0.0.1, so only a wildcard bind (songplayer's, below) collides. A whole-device test that fails at once on its start (bind) while one of theirs runs is that collision. Rerun it alone and check `ps -eo user,args | grep dstack-dev` before calling it ours (1.11.2026: `tests/embed.rs` failed once in 0.01 s, passed 7 times after).
- **Another account's Dante device on dev1** (#278, 13.11.2026): songplayer's tests run a dstack device that binds `0.0.0.0:4440` (ARC), and then every whole-device test (`system_clock`, `embed`, dlink `link`) fails at once with `ARC on UDP 4440: Address already in use`. `ss -lun | grep ':4440 '` shows the wildcard socket (another user's, so `-p` names no process). Rerun those targets once it is gone; CI runs them anyway.
- **Run the full suite with `cargo test`, not `cargo nextest run`** (#292, 14.11.2026): nextest runs each test in its own process, so the in-process `ONE_DEVICE` lock serializes nothing and the whole-device tests (`system_clock`, `embed`, dlink `link`) fail at once with `ARC on UDP 4440: Address already in use` against each other, with no other account on the port. CI runs `cargo test --workspace --locked`; nextest is only the mutation gate's runner (unit tests per mutant).
- **Per-slot state in `RxShared` lives on the heap** (#234): `lanes` is a `Box<[RxStats]>`. A histogram added to `RxStats` (about 5 KB a slot with the wake and network windows) overflowed a test thread's stack while it was a `[RxStats; MAX_FLOWS]` array built by `std::array::from_fn`.
- **Parallel worktrees on dev1:** `ONE_DEVICE` serializes whole-device tests inside one process only. Another autopilot lane's whole-device run (another `.claude/worktrees/agent-*` running `system_clock`, `link` or `embed`) binds the same address (127.0.0.1 since #366) and ports: every test then fails at once at bind (0.07 s), or a later one misses its goodbye or stop. Before calling a failure ours, check `pgrep -af 'deps/system_clock-|deps/link-|deps/embed-'` and rerun when it is empty (#187, 11.11.2026). Even alone, `discovery_lists_our_running_device_and_its_withdrawal` (withdrawal not seen) failed 7 runs in 20 on a loaded dev1 up to v0.6.92: discovery read the busy LAN mDNS group slower than it came and the kernel dropped the goodbye (#206, fixed: `discover::drain`). A "stop not Done" of `two_devices_share_one_address_each_on_its_own_ports` did not reproduce in 40 runs under load alone.
- **Timing on CI and dev boxes:** a normal-priority TX thread wakes over 1 ms late now and then; at the test config's 1 ms latency that restarts the TX schedule (a 2 to 5 ms RX dropout). Whole-path tests use a 10 ms latency, take their counts after the start (0.1 s of RX read), and require no restart and every packet within the latency; real-time lateness is the hardware gate's, never a shared runner's.
- **Docs before a push:** CI's fmt job runs `RUSTDOCFLAGS="-D warnings" cargo doc --workspace --no-deps --locked`. A public item's doc that links a private one (`[`wants_mmcss`]`) fails it, while clippy and the tests pass (v0.6.57 took a second CI round). Run it locally. A function re-exported beside a private module of the same name (`ctl::status`, #211) makes `[`status`]` ambiguous under `--document-private-items`: link it as `[`status`](fn@status)`.
- **Check the Windows build before a push:** `cargo clippy --target x86_64-pc-windows-gnu --workspace --all-targets --locked -- -D warnings` (the target is on dev1 since 2.11.2026). An unused import under `cfg(unix)` costs a 20-minute CI round otherwise (0.4.34 took three).
- **Windows CI runs every test:** paths must be absolute on Windows too (`std::env::temp_dir()`), not `/run/...`.
- **Async inputs:** the directory's ARC and DBC records come from direct mDNS queries (no browse since v0.6.56, #141), taken into the book at each lookup of that device. A test answers them with our own responder's `announce::responder::answers` on loopback (`directory/tests.rs::responder`) and waits for `records().arc_at(..)` before the lookup it counts. A channel's own query keeps it from the ARC for `instance::GRACE_NS`: drive the time with `Instances::with_clock` rather than wait 8 s. A daemon test whose lookups must reach the network serves on `NetInfo { ip: LOCALHOST, .. }` with `Multicast::mdns` at a loopback `Responder`; the tests' 10.0.0.10 cannot bind, which leaves both query threads unstarted (a warning).
- **Mutation gate:** per mutant only the unit tests and `tests/hot_path.rs` run (`.cargo/mutants.toml`); a whole-device test cannot run per mutant (ports). A test bound inside a step must carry the step's own time (`Instant` around `step`), not a fixed bound. Host glue that only calls `daemon::serve` (`host::serve_device`) is covered by the whole-device test alone: any edit inside it, a comment too, puts its `Ok(())` mutant in the diff and fails the gate. Leave such functions out of cosmetic changes.
- **Fake time vs real time:** TX lateness adds real time inside a step to the fake PTP time; bound it by the measured step duration.
- **rtsan only in CI** (#326): dev1 has no nightly, and a project account may not install one (`rustup toolchain install` is hook-blocked; tools come system-wide from airuleset). Locally `tests/rtsan.rs` runs as a plain test; the sanitizer build is the CI `rtsan` job's. Code that must stay real-time safe but contains a system call by nature (the pump's socket drain) keeps the syscall outside the `sanitize(realtime = "nonblocking")` function and puts the attribute on the part after it (`media::rx::intake::place`).
- **Captured logs:** a test that captures logs with `tracing::subscriber::with_default` calls `crate::test_log::undecided()` first. Without it, tracing's callsite interest cache can keep "never" for a callsite another test thread hit first, and the capture comes back empty about 1 run in 4.
- **Equivalent mutants:** combine disjoint bit fields with `from_be_bytes`, not `(a << 16) | b`. cargo-mutants turns `|` into `^`, which gives the same value, so the mutant cannot be killed. Likewise `2 * X` with a constant X = 2 equals `2 + X`: write sums (`X + S + X`), not the product (dtray's icon, v0.6.15). A `const` item is mutated too: `const F: u8 = A | B;` of disjoint bits leaves the `^` mutant; write the byte as one documented literal (dstack #222, `arc::COUNTS_FLAGS`), and set a byte known to be 0 with `=` rather than `|=`.
- **Inside a `.claude/worktrees/` worktree** `cargo fmt --all` fails: `vendor/mdns-sd` resolves the main checkout's workspace. Check with `rustfmt --check --edition 2024` on each crate root (`crates/*/src/lib.rs`, `main.rs`, Windows-only module files) instead; it follows the `mod` tree.
- **A local test device for a reader (dtray):** `DSTACK_TEST_LOOPBACK=1 dstack-dev --config <cfg> --ip 127.0.0.1 --clock system --control <short path>` (loopback: nothing reaches the LAN, #366; a reader on the same box finds it), stopped with `kill -INT`. The control socket path must fit SUN_LEN (about 107 bytes): a scratchpad path is too long, so use a short `/tmp/<dir>/c.sock`.
- **dtray's expected devices in a check:** `DSTACK_DEVICES_DIR=/tmp/<dir>/devices dtray --print` reads that folder instead of `/etc/dstack/devices`; an empty `<name>.device` there with no running device prints "<name>: expected, not running".
- **dtray's source switches in a check** (#210): `DSTACK_SWITCHES=/tmp/<dir>/switches.toml dtray --switch <label> <source>` (and `--print`) against a local `dstack-dev` that is both the receiver and the sources (our device subscribed to itself, made-up names); its state file keeps the subscriptions across restarts, so the first `--print` shows the last run's source. A switch's receiver is on another host in the field: its ARC exchange binds the own address whose discovery found it (`dtray::arc::call_from`, `discover::remote`); `arc::call` binds the ARC's own address and works for local devices only.
- **dtray's latency write in a check** (#213): a `dstack-dev` config with `tx_latency_ns = 1000000` (default `low_latency` timing) states 0.25 ms as its minimum, so `dtray --set-latency <name> 0.333` and back to `1` run there; under `timing = "normal"` the minimum is 4 ms. The range always includes the configured `latency_ns` (`DeviceConfig::latency_range`).
- **A GUI-subsystem binary's console attach** (dtray, dlisten, dsend on Windows) never runs in the Linux gate. Its proof is a test of the binary from the outside through pipes (`crates/dtray/tests/cli.rs`, `crates/dlisten/tests/cli.rs`: `--version`, a usage error; no discovery, no port), which Windows CI runs with the attach in place. The interactive prompt itself is not covered by any test.
- **A console program for scripts on Windows** (dtray-cli, #218): a pipe test from Rust (`Command::output`) passes for a GUI-subsystem exe too, since `CreateProcess` + wait works for both. PowerShell also waits for a GUI exe whose output it captures (`$v = & x.exe`, `& x.exe | ...`). It does not wait in the form a remote shell runs: `&` uncaptured, inside a `powershell.exe` whose own stdout is a pipe. Then the lines are lost and `$LASTEXITCODE` stays empty. So test that form (`crates/dtray/tests/dtray_cli.rs`), plus the PE header's Subsystem (3 console, 2 GUI; the optional header's offset 68). Locally, `x86_64-w64-mingw32-objdump -p <exe> | grep Subsystem` shows it. Under PowerShell 5.1 a native stderr line can come back as an ErrorRecord (`"$_"` is its text, `Out-String` adds position lines), so match stderr with `contains`.
- **A process-wide warn limiter** (#321, `network_floor::WARNED`, keyed by binary, once an hour): every test that counts its warning uses a name no other test uses (`floor-test-*`, `ctl-test-old`), since the limiter outlives the test. A pre-parse header check on a hot receive loop (`arc_versions`' QR bit) needs a boundary test at the exact bit value (byte 2 = 0x80 and 0x7f), or `>=` to `>` survives.
- **A warn-once flag** (`!flag.swap(true)`): the test makes at least three refusals and counts one warning. With two, the `delete !` mutant (warn from the second on) also warns once and survives (v0.6.18, `Media::app_status`). A warning that depends on an error kind goes in a pure function returning the text (`expected::unreadable`): two arms that both return empty leave the guard's mutants unkillable otherwise.
- **Warnings from a background thread:** `capture_warnings` sees only its own thread's events. A warn-once raised on a worker thread (the app hook's `dstack-app-status`) cannot be counted, and its guard's mutants survive. Let the thread mark the state and warn on the reader's thread (`AppHook::read`, v0.6.19).

- **Live tests on dev1's Dante NIC** (`dante-net`; the address is in the private config): run the device with `--ip <that address>` and a private config (through `cargo run` it needs `DSTACK_LIVE_TEST=1`, the workspace's test run refuses a site address, #366; keep it short and name it on the ticket that ran it), write its pid to a file, and stop it with `kill -INT <pid>`, which sends the goodbyes. - **Unreachable guards:** a run-time check that can never be false, given what the code before it already limits, is a mutant no test can kill. Prove the bound once with `const _: () = assert!(...)` and drop the check (example: the fpp step in `subscribe.rs`: 9 + 8 * 4 * 32 <= 1472).
- **Windows-only code and the gate:** the mutation gate runs on Linux, so mutants in `cfg(windows)` code can never be caught. `clock/sys_windows.rs` is excluded in `.cargo/mutants.toml`. Keep Windows logic that matters in cross-platform functions with tests (e.g. `clock::wait_mode_for`, `clock::realtime_for`), and leave the `cfg(windows)` part as thin glue. A cross-platform hook that only Windows code reads (v0.6.35: `clock::set_pinned`/`pinned`, `RePin::keep`'s mark) still needs a Linux test of its own; the Windows test that proves the behaviour never runs in the gate (PR #128 missed 4 mutants that way).
- **Latency verdict = a real receiver's records, never our counters** (owner, 31.10.2026). Dante heartbeats (224.0.0.233:8708) carry per RX flow slot: record 0x8003 = that second's peak lateness in samples, 0x8004 = cumulative late count (header: count, 0, offset of the values). Map slot to transmitter with ARC 0x3000 + 0x3200 (page body `0,1,start,0,0`). Probe: `~/.claude/work-products/dstack/rxlat.py <our ip> <receiver ip> <s>` (exit 1 on late or peak over latency). Every gen3 fault tonight (deep C-states, TX/RX same FIFO priority on one core, fq_codel qdisc) was invisible to our counters; checklist in `docs/linux-box.md`; Windows (FOH PC, 1.11: spinning threads on the NIC's RSS CPUs, a NIC shared with bulk TCP) in `docs/windows-box.md`.
- **The IEM card is shared with iemmixer's box:** use only card RX 104/105, tell iemmixer before subscribing, unsubscribe and stop the dev1 device after; a second sender on the card spoils its measurements.
- **Constant bounds:** clippy refuses `assert!` on constants inside a test; put `const _: () = assert!(...)` next to the constant.
- **Windows runners refuse some high ports** (excluded port ranges, WSAEACCES 10013): a test never binds a fixed port near 65535 and never relies on binding in order to reach a range check (v0.4.39: the RX port-base test failed on 65531). Pure range logic gets a pure function and a boundary test.
- **Probing hardware on 8700:** a device answers on the info group 224.0.0.231:8702, from its own port, with its own sequence number (not the request's). Match a reply by source address and reply opcode, never by seq. Dante Controller caches a device's answers: to capture its full read sequence, restart DC under the capture (pktmon on mbc, filtered by control ports, without the 614xx audio range).
- **Socket loops and the gate:** put each read's decision (hand on, go on after a timeout, end on an error) in a pure function that takes the `io::Result`, and unit test every arm (`latency::hand_on`). On dev1 other devices' heartbeats fill every gap, so a test cannot count on a read timing out on a real group socket. A loop over several sockets with read timeouts drains each one while it has datagrams (`discover::drain`): one read per socket a pass waits the idle socket's timeout every pass, and a busy group (dev1's LAN mDNS: about 30 datagrams/s) then overflows its queue and the kernel drops datagrams (#206: 189 KB queued, up to 73 drops a run). Check a suspect socket's `/proc/net/udp` queue and drops column while the test runs.
- **A race between two locked reads** (#269, v0.6.120): a decision a caller builds from two calls that each lock shared state (`Network::lookup` read the record, then the grace) races with any thread that writes between them; a CI failure once in N runs that loops under load 0/60 and with a late thread start 0/30 is this. Prove it with a temporary sleep between the two reads (20/20), then a test with no sleep: one thread feeds real answers (`Instances::answer` with `announce::responder::answers`, the host's A too) while the test looks up and forgets the record after each find, until N finds within `BOUND` (`directory/tests/record_race.rs`). Count finds, not rounds: on one CPU or at load ~36 the feeding thread runs rarely (200 finds overran 5 s; 50 still fail 40/40 without the fix). The fix reads both under one lock (`Table::direct`), never a re-check.
- **Load reproductions on dev1:** no stress-ng; `(while :; do :; done) &` per busy loop (24 = load ~28, 64 = load ~80). A loop script whose own arguments name `deps/system_clock-...` matches the parallel-lane `pgrep -f` check itself and waits forever: anchor it (`pgrep -f '^[^ ]*deps/(system_clock|link|embed)-'`) and run a copy of the test binary named `.../deps/system_clock-<x>`, so other lanes' checks still see it and a rebuild does not swap it mid-loop.

- **The local mutation gate** is cargo-mutants 27.1.0 (as CI) since 3.11.2026. - **A narrowed local mutation run** (#328): `.cargo/mutants.toml` already adds `--lib --test hot_path` to every nextest call, so after `--` give only a name filter (`cargo mutants --in-diff <diff> --package dstack -- clock::skewed`). - **Thread stress tests on runners:** a spawned thread can start tens of ms late on a runner, which never happens on dev1. Before calling a stress-test fix done, reproduce the runner's order locally with a temporary `sleep(50 ms)` at the thread's start (v0.6.8: the ring's reader started late; with no read yet `write_at` has no early check, and the test failed twice on CI after passing 15/15 locally). Prime the shared state the check needs (`read_at` before the writer) instead of loosening the invariant.
- **Exclusion patterns match prefixes:** `.cargo/mutants.toml`'s `exclude_re` entries are regexes over the mutant's name (`tx/thread.rs.*send_one`), so a new function named `send_one_retrying` would be excluded silently and its mutants never tested. Name a new tested helper so no exclusion matches it (v0.6.21: `send_with_retries`).
- **A wait loop with a comparison** (`while start.elapsed() < d`) leaves the `<` to `<=` mutant, which waits the same and cannot be killed. Write it without a comparison: `while !d.saturating_sub(start.elapsed()).is_zero()`, and test that it waits at least `d` (v0.6.21, `media::tx::spin_for`).
- **Retry loops in the TX pass:** keep the loop generic over closures (`send`, `age`, `wait`; `media::tx::send_with_retries`) so a unit test drives it with a fake send that fails with given OS codes; the real socket never refuses on demand. Generic closures keep the hot path allocation-free.
- **dlink's pump block is 128 frames by default** (v0.6.20, #90), not the stack's `stream::BLOCK` 32. Its whole-device expectations follow it: `pump.offset` = B + P + W (848 at 48 kHz, 1507 for a 48 kHz app on a 96 kHz device at the defaults; the tests derive them from `Config::split`), and a 48 kHz app on a 96 kHz device gets 64 frames a block. A dlink test about something else that needs 32-frame blocks sets `.block(32)`. **The latency is named terms since v0.6.106 (#244):** P = (a) `network_latency_ns` (1 ms default) + (b) `receive_buffer_ns`, rounded UP to whole samples (`Split::receive_buffer_ns` is P - a, so the terms add up); (c) the hand-off is computed (RX B + converter, TX W + converter).
