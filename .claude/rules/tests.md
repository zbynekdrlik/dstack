# Tests in dstack

- **Whole-device tests run on loopback** (#366, `host::test_run`): every process cargo runs in this workspace has `DSTACK_TEST_LOOPBACK=1` (`.cargo/config.toml` `[env]`, nextest and cargo-mutants included), and then the host serves a device on 127.0.0.1 (a test MAC `02:00:7f:00:00:01`) and REFUSES any other address the lookup finds unless `DSTACK_LIVE_TEST=1` (a place not there yet is judged as in production, so the "address not there" start tests still run). Each file's `test_ipv4()` returns `Ipv4Addr::LOCALHOST`; never probe the routed address (192.0.2.1:9) for a device again: on dev1 that announced ~35 mDNS datagrams/s per binary on the LAN leg, the top senders on FOH's Dante leg (dasio#127). Loopback multicast works on Linux and Windows (`IP_MULTICAST_IF` 127.0.0.1, a member joined on 127.0.0.1). A test binary run directly (`target/debug/deps/system_clock-*`) has no variable: production refuses loopback, so run it through `cargo test` or with `DSTACK_TEST_LOOPBACK=1` set. Each test binds the Dante ports on 127.0.0.1: take the file's `ONE_DEVICE` lock. A test that sends multicast with its own socket (`mdns_answer_only`, `announce::mdns`'s) uses 127.0.0.1 too; the guard covers only devices the host starts. Count dev1's own mDNS on both legs with a `python3 -I` listener on 224.0.0.251:5353 joined on each leg's address (counts by source; the kernel loops our own sends back): while the whole set ran (150 s, 17.11.2026) 0 on the Dante leg and 2 on the LAN leg, from no device of ours (before: `system_clock` alone sent 780 there in 22 s). The guard judges the address the lookup FOUND (`TestRun::admit`), never the place asked: a first draft refused every non-loopback place up front and broke the dlink start tests on an absent address. On loopback the load-sensitive dlink tests stay load-sensitive (`a_pump_late_within_its_margin_keeps_the_tone_whole` failed 1 of 2 at load 20, passed 5 of 5 under `DSTACK_TEST_LOOPBACK=1 chrt -f 10 <binary>`).
- **Shared dev box:** dcontroller (another account on dev1) runs `dstack-dev` in its own E2E on the routed address and Dante ports; since #366 ours are on 127.0.0.1, so only a wildcard bind (songplayer's, below) collides. A whole-device test that fails at once on its start (bind) while one of theirs runs is that collision. Rerun it alone and check `ps -eo user,args | grep dstack-dev` before calling it ours (1.11.2026: `tests/embed.rs` failed once in 0.01 s, passed 7 times after).
- **Another account's Dante device on dev1** (#278, 13.11.2026): songplayer's tests run a dstack device that binds `0.0.0.0:4440` (ARC), and then every whole-device test (`system_clock`, `embed`, dlink `link`) fails at once with `ARC on UDP 4440: Address already in use`. `ss -lun | grep ':4440 '` shows the wildcard socket (another user's, so `-p` names no process). Rerun those targets once it is gone; CI runs them anyway.
- **Run the full suite with `cargo test`, not `cargo nextest run`** (#292, 14.11.2026): nextest runs each test in its own process, so the in-process `ONE_DEVICE` lock serializes nothing and the whole-device tests (`system_clock`, `embed`, dlink `link`) fail at once with `ARC on UDP 4440: Address already in use` against each other, with no other account on the port. CI runs `cargo test --workspace --locked`; nextest is only the mutation gate's runner (unit tests per mutant).
- **Per-slot state in `RxShared` lives on the heap** (#234): `lanes` is a `Box<[RxStats]>`. A histogram added to `RxStats` (about 5 KB a slot with the wake and network windows) overflowed a test thread's stack while it was a `[RxStats; MAX_FLOWS]` array built by `std::array::from_fn`.
- **Parallel worktrees on dev1:** `ONE_DEVICE` serializes whole-device tests inside one process only. Another autopilot lane's whole-device run (another `.claude/worktrees/agent-*` running `system_clock`, `link` or `embed`) binds the same address (127.0.0.1 since #366) and ports: every test then fails at once at bind (0.07 s), or a later one misses its goodbye or stop. Before calling a failure ours, check `pgrep -af 'deps/system_clock-|deps/link-|deps/embed-'` and rerun when it is empty (#187, 11.11.2026). Other lanes' dlink loops hold the port too (#442, 19.11.2026: a lane's `rx_pull_held` looped on 127.0.0.1:4440 for minutes): name the holder with `ss -lunp | grep '127.0.0.1:4440 '`, and run the whole-device binaries from a script that waits until that line is gone and reruns a binary whose output says `Address already in use`. Even alone, `discovery_lists_our_running_device_and_its_withdrawal` (withdrawal not seen) failed 7 runs in 20 on a loaded dev1 up to v0.6.92: discovery read the busy LAN mDNS group slower than it came and the kernel dropped the goodbye (#206, fixed: `discover::drain`). A "stop not Done" of `two_devices_share_one_address_each_on_its_own_ports` did not reproduce in 40 runs under load alone.
- **Timing on CI and dev boxes:** a normal-priority TX thread wakes over 1 ms late now and then; at the test config's 1 ms latency that restarts the TX schedule (a 2 to 5 ms RX dropout). Whole-path tests use a 10 ms latency, take their counts after the start (0.1 s of RX read), and require no restart and every packet within the latency; real-time lateness is the hardware gate's, never a shared runner's.
- **Docs before a push:** CI's fmt job runs `RUSTDOCFLAGS="-D warnings" cargo doc --workspace --no-deps --locked`. A public item's doc that links a private one (`[`wants_mmcss`]`) fails it, while clippy and the tests pass (v0.6.57 took a second CI round). Run it locally. A function re-exported beside a private module of the same name (`ctl::status`, #211) makes `[`status`]` ambiguous under `--document-private-items`: link it as `[`status`](fn@status)`.
- **Check the Windows build before a push:** `cargo clippy --target x86_64-pc-windows-gnu --workspace --all-targets --locked -- -D warnings` (the target is on dev1 since 2.11.2026). An unused import under `cfg(unix)` costs a 20-minute CI round otherwise (0.4.34 took three).
- **Windows CI runs every test:** paths must be absolute on Windows too (`std::env::temp_dir()`), not `/run/...`.
- **Async inputs:** the directory's ARC and DBC records come from direct mDNS queries (no browse since v0.6.56, #141), taken into the book at each lookup of that device. A test answers them with our own responder's `announce::responder::answers` on loopback (`directory/tests.rs::responder`) and waits for `records().arc_at(..)` before the lookup it counts. A channel's own query keeps it from the ARC for `instance::GRACE_NS`: drive the time with `Instances::with_clock` rather than wait 8 s. A daemon test whose lookups must reach the network serves on `NetInfo { ip: LOCALHOST, .. }` with `Multicast::mdns` at a loopback `Responder`; the tests' 10.0.0.10 cannot bind, which leaves both query threads unstarted (a warning).
- **Mutation gate:** per mutant only the unit tests and `tests/hot_path.rs` run (`.cargo/mutants.toml`); a whole-device test cannot run per mutant (ports). A test bound inside a step must carry the step's own time (`Instant` around `step`), not a fixed bound. Host glue that only calls `daemon::serve` (`host::serve_device`) is covered by the whole-device test alone: any edit inside it, a comment too, puts its `Ok(())` mutant in the diff and fails the gate. Leave such functions out of cosmetic changes.
- **Fake time vs real time:** TX lateness adds real time inside a step to the fake PTP time; bound it by the measured step duration.
- **rtsan only in CI** (#326): dev1 has no nightly, and a project account may not install one (`rustup toolchain install` is hook-blocked; tools come system-wide from airuleset). Locally `tests/rtsan.rs` runs as a plain test; the sanitizer build is the CI `rtsan` job's. Code that must stay real-time safe but contains a system call by nature (the pump's socket drain) keeps the syscall outside the `sanitize(realtime = "nonblocking")` function and puts the attribute on the part after it (`media::rx::intake::place`).
- **Captured logs:** a test that captures logs with `tracing::subscriber::with_default` calls `crate::test_log::undecided()` first. Without it, tracing's callsite interest cache can keep "never" for a callsite another test thread hit first, and the capture comes back empty about 1 run in 4.
- **Equivalent mutants:** combine disjoint bit fields with `from_be_bytes`, not `(a << 16) | b`. cargo-mutants turns `|` into `^`, which gives the same value, so the mutant cannot be killed. Likewise `2 * X` with a constant X = 2 equals `2 + X`: write sums (`X + S + X`), not the product (dtray's icon, v0.6.15). A `const` item is mutated too: `const F: u8 = A | B;` of disjoint bits leaves the `^` mutant; write the byte as one documented literal (dstack #222, `arc::COUNTS_FLAGS`), and set a byte known to be 0 with `=` rather than `|=`.
- **Inside a `.claude/worktrees/` worktree** `cargo fmt --all` fails: `vendor/mdns-sd` resolves the main checkout's workspace. Check with `rustfmt --check --edition 2024` on each crate root (`crates/*/src/lib.rs`, `main.rs`, Windows-only module files) instead; it follows the `mod` tree.

The control socket path must fit SUN_LEN (about 107 bytes): a scratchpad path is too long, so use a short `/tmp/<dir>/c.sock`.

- **dtray's source switches in a check** (#210): `DSTACK_SWITCHES=/tmp/<dir>/switches.toml dtray --switch <label> <source>` (and `--print`) against a local `dstack-dev` that is both the receiver and the sources (our device subscribed to itself, made-up names); its state file keeps the subscriptions across restarts, so the first `--print` shows the last run's source. - **A process-wide warn limiter** (#321, `network_floor::WARNED`, keyed by binary, once an hour): every test that counts its warning uses a name no other test uses (`floor-test-*`, `ctl-test-old`), since the limiter outlives the test. With two, the `delete !` mutant (warn from the second on) also warns once and survives (v0.6.18, `Media::app_status`). - **Warnings from a background thread:** `capture_warnings` sees only its own thread's events. A warn-once raised on a worker thread (the app hook's `dstack-app-status`) cannot be counted, and its guard's mutants survive. - **Unreachable guards:** a run-time check that can never be false, given what the code before it already limits, is a mutant no test can kill. Prove the bound once with `const _: () = assert!(...)` and drop the check (example: the fpp step in `subscribe.rs`: 9 + 8 * 4 * 32 <= 1472).

- **Latency verdict = a real receiver's records, never our counters** (owner, 31.10.2026). Dante heartbeats (224.0.0.233:8708) carry per RX flow slot: record 0x8003 = that second's peak lateness in samples, 0x8004 = cumulative late count (header: count, 0, offset of the values). - **Probing hardware on 8700:** a device answers on the info group 224.0.0.231:8702, from its own port, with its own sequence number (not the request's). Match a reply by source address and reply opcode, never by seq. Dante Controller caches a device's answers: to capture its full read sequence, restart DC under the capture (pktmon on mbc, filtered by control ports, without the 614xx audio range).
- **`/proc/net/udp` skips rows** (#455, 20.11.2026): the kernel hands the table out one page (31 rows) a `read()` and starts each `read()` by walking the table again to the count it gave (`udp_seq_start`), so every row listed earlier that closes between two reads skips a later one (an earlier insert repeats one). `read_to_string` takes several reads (dev1 has 51 rows idle, more while tests run), and a lib run's other tests open and close sockets all the time: the #444 reopen test read no row for a socket that had just answered, 1 full lib run in 23 (a throwaway script: 120 sockets, ours closed between the first `read()` and the rest, left 6 and 10 open ones unlisted). Wait for a read that lists the row needed, judge on that read, and judge a close by the inode leaving `/proc/self/fd` (listed by fd number: exact), never by a row's absence (`announce::mdns::tests::listed_on`, `tests/mdns_one_socket.rs`). An absence check (no socket on an address, no IPv6 socket) can still pass on a read that skipped the row; a count can miss a second socket, never add one. Prove such a wait with a temporary edit that empties every second read (the tests pass) and every read (they fail at the bound).
- **Socket loops and the gate:** put each read's decision (hand on, go on after a timeout, end on an error) in a pure function that takes the `io::Result`, and unit test every arm (`latency::hand_on`). On dev1 other devices' heartbeats fill every gap, so a test cannot count on a read timing out on a real group socket. A loop over several sockets with read timeouts drains each one while it has datagrams (`discover::drain`): one read per socket a pass waits the idle socket's timeout every pass, and a busy group (dev1's LAN mDNS: about 30 datagrams/s) then overflows its queue and the kernel drops datagrams (#206: 189 KB queued, up to 73 drops a run). Check a suspect socket's `/proc/net/udp` queue and drops column while the test runs.

Count finds, not rounds: on one CPU or at load ~36 the feeding thread runs rarely (200 finds overran 5 s; 50 still fail 40/40 without the fix). The fix reads both under one lock (`Table::direct`), never a re-check.
