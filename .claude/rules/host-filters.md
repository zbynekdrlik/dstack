# Host filters (dante-leg.nft, dante-leg-notrack.nft, dante-leg.ps1)

- **notrack breaks NAT and stateful firewalls.** An untracked packet is never NATed, and a stateful rule on another NIC sees its own replies as untracked, not established. So raw `notrack` chains never go into `dante-leg.nft`, which loads on every Linux PC. They live in `dante-leg-notrack.nft`, loaded only on a PC with no Docker, libvirt, masquerade, ufw or firewalld (#264, v0.6.119). Docker runs on the presenter PC and dev1.
- **`oifname` at raw priority in the output hook is reliable.** `__ip_local_out` / `__ip6_local_out` pass the route's device to `NF_INET_LOCAL_OUT`, so no `fib` lookup is needed.
- **Syntax check without root on dev1 fails.** `nft -c` needs netlink, and `unshare -rn` is refused (`apparmor_restrict_unprivileged_userns=1`). Instead, pipe the file to `sudo -n nft -c -D dante_leg=lo -f -` on the presenter PC through its remoteos Shell. `-c` changes nothing, and stdin leaves no file. A load without `-D` fails with "unknown identifier".
- **CI loads the rulesets for real.** `tools/linux/tests/dante-leg.test.sh` runs as root in a private netns (linux-tools job). A new table gets its load, reload, missing-`-D` and behaviour checks there. Behaviour is checked with a test-only counter table and a dummy leg on TEST-NET-1. A `grep -c` on a table name must be exact (`-cx 'table inet …'`), or a sibling table matches too.
- **A rate cap on Linux** (#288): `limit rate over N/second burst B packets counter drop` in chain `out`, first after the leg check. A drop in the output hook fails the sender's `sendto` with EPERM, so the netns test counts what a Python sender got out and compares the rule's counter with the rest; the burst starts full after a load.
- **Queries have their own Linux cap** (#288 step 2, owner 14.11.2026): `@th,80,1 0` (the DNS QR bit: UDP header 8 bytes + the 2-byte DNS id = bit 80; nft lists it as `@th,80,8 & 0x80 == 0x0`) `limit rate over 10/second burst 50 packets counter drop`, before the 50/s rule, which then governs answers. Mutating the rule against the netns test proved the offset (v0.6.131): `@th,80,1 1` lets a 40/s query flood through, `@th,81,1`/`@th,87,1`/`@th,72,1` drop an answer burst. Send real DNS headers there (flags `0x8400` answer, `0x0000` query): an all-zero payload is a query.
- **Windows keeps one 200 kbit/s throttle for all mDNS** (no query cap): a NetQos policy matches protocol, address and port only, never a payload bit, and a lower throttle on all mDNS would delay answer bursts (up to 28 in 100 ms measured).
- **Windows Firewall cannot limit a rate; a NetQos policy can** (#288, `dstack Dante leg mDNS cap`). `New-NetQosPolicy` takes protocol + destination prefix + destination port together and reads back `IPDstPrefixMatchCondition` without `/32`, the port as `IPDstPortStart/EndMatchCondition`, the rate as `ThrottleRateAction` (bits/s, so a cap in datagrams depends on their size; it queues, the sender waits). A policy has no adapter condition: it holds on every adapter. A Realtek Virtual Adapter (VLAN leg) has no `ms_pacer` binding; the base adapter's applies the throttle (measured: 46/s on the wire under 200 kbit/s). Probe a policy shape or its effect with a throwaway policy on an unused link-local group/port (224.0.0.250:45454) and a tcpdump on another PC's leg, then remove it.
- **Running the netns harness before a push:** dev1 has no root; the presenter PC's remoteos Shell has `sudo -n` and `unshare --net`. Push the commit to a `refs/autopilot-wip/...` ref, `curl` the three files by SHA from raw.githubusercontent into a temp dir there, and run `sudo -n bash <dir>/tools/linux/tests/dante-leg.test.sh` (private netns: the PC's own rules are not touched).
