# The TX side (media/tx)

- **Module layout** (#360, after #300's `subscribe` split): `tx.rs` keeps the constants, `TxShared`/`Control`, `Plan`, the seqlocked `Cell`, the per-slot counts (`LaneStats`, `LaneCounts`, `count_send`) and `nanos`; `table.rs` the control side's `TxTable`/`TxFlow` (`multicast.rs` adds the multicast flows to it); `schedule.rs` `Schedule` and the time helpers (`ns_of`, `send_clock`, `flow_latency_ns`, `over_latency`); `thread.rs` the TX thread (`Lane`, `Transmitter` and its pass, `send_one`, `spawn`, the loops and the relay escape); `priority.rs` the OS thread calls (`ask_priority`, the Windows priority mapping, `place`, `pin_to_cpu`) beside `take_priority` and the MMCSS record. Every public name is re-exported at `media::tx::`, so callers and siblings (`use super::ns_of`) never name the file. A `Transmitter` field a sibling's `impl Transmitter` reads (`split.rs`, `shift.rs`) is `pub(super)`. The tests read names through `use super::*`, so a name only they use is a `#[cfg(test)]` import in `tx.rs` (`escape_through`, `run_relay`, `run_with`, `send_one`, `pin_to_cpu`; `ask_priority` only under `cfg(all(test, windows))`). A function that moves files takes its `.cargo/mutants.toml` `exclude_re` path along (`tx/thread.rs.*send_one`, `tx/priority.rs.*unthrottle`).
- **The TX pull** (#363, `tx/fill.rs`): an app's TX `Process` (dlink's `TxPull`, behind `Rated` when converting) claimed once with `TxShared::claim_fill` before the TX thread builds its state (`Transmitter::new` takes it after `host_for_tx` closes the claims, under the control lock), so each engine ring keeps ONE writer: the pump or the TX thread, never both (`engine_channels` refuses a channel in both maps). Each pass runs `fill_due` before `send_due` (`step` and `before_wait`'s last pass alike), on the pump's own `stream::Blocks` with the schedule's margin set to the fill's reach (W + the advertised latency, the flows' `max_lag`); D for the stamp is the real W (`Timing::offset`). A new P (`RxShared::playout`) or `max_lag` restarts it (counted), a re-anchor goes through `re_anchored` with the media clock (not the send clock). `wake_ns` includes the fill's next due time, so the TX thread wakes at the pump's times. A whole-device proof is `dlink/tests/tx_pull.rs` (pump stalls 10-20 ms against a steady 10 ms app writer: 0 off, 0 TX holes, 0 writes after send, 0 underruns); a fill unit test that needs the TX thread to stay under its 1 ms test latency steps under 1 ms apart (1.5 ms restarts the flows' schedule, which is not the fill's doing).
