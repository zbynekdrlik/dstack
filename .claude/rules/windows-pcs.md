# Windows PCs: network legs and the tools for them

- **One NIC stays** (owner 12.11.2026, #239): never propose two NICs again. The vendor VLAN tool (Realtek `8169DiagV2.exe`) never stays running after setup; close it without clicking its dialogs. A Realtek VLAN adapter's MAC changes on a USB replug and on every base-adapter restart.
- **Every one-NIC PC gets the LAN self-heal task** (`tools/windows/lan-selfheal.ps1 -Mode install`, docs/two-networks.md section 3). The VLAN property is found by its display name "VLAN ID": its keyword is the driver's (`RegVlanID` on the RTL8156 base adapter, `VlanID` on the Realtek Virtual Adapter). The config's `lanVlanId` (required since 0.6.105) states the LAN adapter's VLAN: 0 when the LAN is the untagged base adapter, N when the LAN is a VLAN adapter (a dasio host keeps Dante untagged on the base adapter); a script change that adds a required config key also migrates every installed config.
- **Never disable, enable or restart a Realtek Virtual Adapter** (#239): `Disable-NetAdapter` on one (driver 10.4.1117.2020) bugchecked dasio's test PC on 13.11.2026, and `Restart-NetAdapter` is a disable plus an enable. Not by hand, not in a script, not in a LAN-down test: change its VLAN ID (`-NoRestart`), bindings and DHCP in place and renew its lease. lan-selfheal (0.6.115+) detects one by `InterfaceDescription` (`Test-VirtualVlanAdapter`) and never cycles it; a layout-B LAN-down test cuts the LAN another way (unbind IPv4, or the switch port), never by disabling the adapter. Restarting a physical base adapter (layout A) is fine.
- **A LAN-down test** (disabling the LAN leg on purpose) is a separate run the owner times; installing and checking "gateway ok" is not.
- **Testing a PowerShell tool:** dev1 has no `pwsh`. CI's `windows-tools` job runs `tools/windows/tests/*.Tests.ps1` under Windows PowerShell 5.1 (plain asserts, no Pester: inbox 3.4 and runner 5.x differ). Before the push, push the commit to a new `refs/autopilot-wip/<branch>-<topic>` ref per commit (a force push to an existing wip ref is hook-blocked) and fetch the files on a Windows PC by SHA from `raw.githubusercontent.com/zbynekdrlik/dstack/<sha>/...` (check `Get-FileHash`), then run the test there: no 20 KB paste through MCP. `dante-leg.Tests.ps1`'s last part creates a real (disabled) group and a real QoS policy: on a field PC where nothing may be installed, run the file cut before its `the real firewall, disabled` marker (plus the passed/failed summary lines) and leave that part to CI; check the whole file with `[System.Management.Automation.Language.Parser]::ParseFile` (#288).
- **PowerShell strings:** `"$var: text"` is a parse error (`:` after a variable reads as a scope); write `"${var}: text"`. A function whose value is an exit code must not leak cmdlet output into it: take the last value (`$rc | Select-Object -Last 1`). Under `Set-StrictMode -Version 2` a function that returns an empty array gives `$null`, and `$null.Count` throws: count with `@(f).Count`.
- **Testing adapter changes without an adapter:** define functions named like the NetAdapter/NetTCPIP cmdlets in the test script after dot-sourcing the tool (a function wins over a cmdlet) and record each call's target; the heal path then runs on CI with no NIC touched (`tools/windows/tests/lan-selfheal.Tests.ps1`).
- **dasio's PCs** (its test PC, FOH, its Dante Controller PC): dstack does no Windows OS work there; it gives the tool and the plan on the ticket.
- **Windows Firewall: an explicit Block rule beats every Allow rule** (only an IPsec "override block rules" Allow wins), and every matching Block rule blocks: to open a port, narrow EVERY Block rule that covers it, never add an Allow rule. ssh (22) and the remoteos MCP (8092) are open on the Dante leg (owner 13.11.2026, #239): the `dstack155` TCP-in rule blocks `'1-21','23-8091','8093-65535'` only, and the MCP's runtime rule (`python.exe`, all protocols) is narrowed to UDP, or it still blocks 8092. Check a port's opening by a TCP connect from another host's Dante leg, not by reading one rule. `LocalPort` ranges and a mixed IPv4+IPv6 `RemoteAddress` list are accepted by `New-/Set-NetFirewallRule`; probe a new argument shape live with a disabled throwaway rule and remove it.
- **Proving a port is closed on a PC's Dante address:** from dev1 bind the Dante address (`socket.bind(('<dev1 dante>',0))`, or `ssh -b`), but dev1's own `dante_guard` chain `out` drops every TCP port except 22 and 8092, so a timeout on 445 there proves nothing about the PC (read its drop counter). companion-snv and stream-snv drop TCP out on their Dante legs too. Prove the closed side from the PC's rules (the port listening + inside the TCP-in rule's ranges), and the open side by a connect (22 banner, 8092 `GET /health` 200).
- **lan-selfheal 0.6.109's emergency path is removed** (0.6.111): its config keys are accepted and logged as ignored, and every full check (the loop's first minute, every minute after a failed quick check) enables a `dstack155` rule it left disabled before removing the `dstack emergency` rules. Never bring back an outage-only or single-source opening.
- **A periodic Windows tool runs as one long-lived loop, never a process a minute** (#312): a new `powershell.exe` that imports NetAdapter/NetTCPIP/NetSecurity and runs CIM queries costs ~2.4 s wall and ~1.6 s CPU, plus ~0.5 s in WmiPrvSE (iem-snv, Ryzen 5800X); `Get-NetFirewallRule` alone ~745 ms cold. That stall made an audio pump on the PC wake late at the task's start second. lan-selfheal's healthy minute uses only .NET (`NetworkInterface`, a UDP connect's `LocalEndPoint` as the route's source address, one `Ping`: ~8 ms) at BelowNormal; CIM runs only on a failed quick check. Task Scheduler's restart-on-failure covers only a failed start: a long-lived task also gets a repetition watchdog trigger with `MultipleInstances IgnoreNew` (no process while it runs), `ExecutionTimeLimit` zero (reads back `PT0S`), and install stops the running instance before re-registering. A test can override any function of the dot-sourced tool inside a `Check` block (dynamic scope) to force one path, and keep the real one in a variable first (`${function:Name}`) to test it for real.
- **The Bash tool moves a call to the background after 180 s** in a dispatched worker: poll CI with short separate calls (one `gh run view` each), never one long loop.
- **The generic Dante-leg group** (`tools/windows/dante-leg.ps1`, #264): Block rules for the complement of the Dante sets (a rule's conditions are ANDed, so "from 5353 to ephemeral ports" is its own rule). Its test installs a DISABLED copy under a test group on the CI runner's real adapter and reads it back with the real `Get-NetFirewall*Filter` cmdlets: the stored shapes (port lists, `%SystemRoot%` program paths, IPv4 range lists) read back as given. Never install it enabled on a runner (its TCP-out rule would cut the runner off). PowerShell 5.1 traps met there: a `Mandatory` string parameter given `''` fails in binding ("empty string") before the body runs; a function returning `, $array` hands `@(f)` ONE element (count 1 even when empty), so emit items and wrap only pairs (`, $pair`); `$args` and `$profile` are automatic variables.
- **pktmon on a Windows PC** (#425): `pktmon list -a` gives the component ids (TCPIP on the VLAN adapter, NetAdapterCx `netadaptercx.sys`, the miniport); capture only those (`--comp <ids> --pkt-size 64`). `etl2txt --hex` writes UTF-16, ~45 MB of text per MB of etl. pktmon logs only the first packet of an NBL chain, so time packets by their Dante stamp and trust maxima, not counts. A fleet MCP Shell call longer than ~60 s returns `ReadError` and can leave a capture running: start a capture of 60 s or less as a detached `Start-Process powershell -File cap.ps1` whose `finally` runs `pktmon stop` and `pktmon filter remove`, read the receiver meanwhile, then check `pktmon status`. A USB RTL8156 under Microsoft's inbox NetAdapterCx driver (`rtucx21x64`) has ONE send queue: a Dante packet waits behind whatever else the PC sends (resolume-pp: NDI frames of 0.4-0.9 MB at 30 fps), and 802.1p or switch shaping cannot help.
