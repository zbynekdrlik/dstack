# The info port (8700) and dstack-own requests

- **A dstack-own request answers UNICAST to the asker, never to the info group** (#391, the bridge figures, `info::bridge`): 224.0.0.231:8702 and the heartbeat group are read by Dante Controller and every Audinate device, so a vendor packet there risks every reader for one consumer. Pick its opcode outside Audinate's message types on 8700 (seen: 0x00xx, 0x01xx, 0x10xx, 0xffxx in inferno, netaudio-core `commands/*.rs` and our captures; dstack's are 0xd5xx), keep it out of the group path (`answer` returns `None`, `answer_within` skips the bound for it) and bound it as a kind of its own.
- **Several devices on one address:** a member never sees the asker's address, so the manager relays such a request as `share::Msg::Ask(asker, ..)` and sends the member's `Msg::SendTo` from 8700. Guard that path (`share::Asks`, `is_bridge_reply`, `is_unicast`): without it any local process that registers could send any bytes from the Dante info port to any address. An older manager or member drops the new messages; the CHANGELOG says so (every app on a dasio PC must take the release).
- **A fixed-layout body grows by version, appended** (#419, the bridge figures' version 2: through-latency each way and the ASIO driver's name at 0x78..0xC0 after version 1's 120 bytes, unchanged). The writer writes the newest version only; the reader takes each version at its own exact length (an old body's new fields read `None`) and refuses anything else, so an old reader refuses the new reply (`Malformed`): the reader's consumer (dcontroller) takes the release first, then the writer's app (dasio) moves. `share::is_bridge_reply` accepts every version's length, so a newer manager still hands over an older member's reply (an older manager drops a newer member's). A text field is a length byte + a fixed zero-padded room, cut at a char boundary on the WRITE side (`driver_cut`, also in the slot's setter, so the slot's figures equal what the wire carries); the reader refuses a length past the room and non-UTF-8. A 0 or an empty name on the wire is "not known", `None` in the struct. The version 1 body for the tests is written byte by byte from the walker's own table (`version_1` in `info/tests/bridge.rs`), never by our writer.
- **The clock figures** (#429, `info::clock_figures`, `07 xx d5 b3` / `07 2a d5 b2`, 66 bytes version 1, for dcontroller#124): every running device answers, with no app hand-over: `Beat::clock_figures` of the running device (`server::Sources`) builds them from the clock's stats (`figures_of`: `ClockStats` source/linked/follower, the poller's read `ClockStats::service`, its counts and grandmaster). Only what the stack reads goes on the wire: DSYX has no phase error, so dsync's `ptp_phase_error_us` is not there (its `:8898` is dcontroller's own read over the LAN). Name a field for its meaning (`follower_error_p90_ns` is dsync's `recent_abs_e_ns`, never `offset_ns`; `follower_offset_from_service_ns` is set only while the selector waits to agree, `Report::offset_from_service_ns` beside `waiting`). Not known is a sentinel (`i64::MIN`, `u32::MAX` age, zero UUID) read as `None`; an absent part (`follower` 0, `service_poll` 0) is all zeros and its bytes are not read; a flag byte past 1 or a code past its table is refused (`ClockFiguresError::Code` names the byte). The manager hands a member's reply over only as a bridge or a clock reply (`share::is_clock_reply`); `relay_of` relays both requests as `Msg::Ask`; the member tries `bridge_within` then `clock_within` (each answers its own kind only). The flags cannot all differ in one body, so the codec test sets each alone (`each_flag_alone_sits_at_its_own_key`); a swap of `FOLLOWER_HOLDOVERS`/`SERVICE_HOLDOVERS` in the writer's `at` fails 7 walker tests while our own round trip passes.
- **Read the figures after the bound:** `bridge_within` checks the slot's source, then the bound, then reads (the source takes the runner's status lock), so a flood reads at most `PER_SPAN` a second; `clock_within` takes its read as a closure, called only past the bound (the stats' locks).
- **Tests:** a fixed-layout packet still gets an independent walker (`tests/conformance/bridge_figures.rs`, its own offset table, every field's bytes distinct so a swapped offset shows); prove it bites by swapping two offsets in the writer's `at` table (our own round trip still passes, the walker tests fail). A `match` arm guard (`if from == manager`) is mutated by cargo-mutants: test the arm with a stranger's message. The manager's `select!` picks a ready arm at random: a test that sends a share message and then a request waits for the first's effect (or its absence) before sending the second.
